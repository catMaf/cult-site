# Cult Place — лендинг

Статический одностраничник лофт-пространства в Минске (ул. Куйбышева, 22, пространство 118Б).
Сборки нет: три файла + картинки, раздаётся nginx в контейнере.

Документ ведётся как рабочий журнал: помимо описания проекта здесь зафиксировано,
**какие проблемы решались и почему решения именно такие**. Он написан, чтобы
восстановить контекст в новой сессии, не перечитывая diff.

---

## Запуск

```bash
docker compose up --build     # http://localhost:8080
```

Для быстрой правки достаточно открыть `index.html` в браузере — внешних зависимостей,
кроме Google Fonts, нет.

## Структура

```
index.html          вся разметка
css/styles.css      все стили (~1400 строк, организованы по секциям)
js/main.js          один IIFE: лайтбокс, галерея, искры на canvas
assets/images/      боевые картинки
fotos/, ref/        исходники и референсы, в образ не попадают
nginx.conf          gzip, кэш, security-заголовки
Dockerfile          nginx:1.27-alpine + копирование статики
rules/              правила проекта (качество изображений, дизайн-система)
```

## Стек

- Vanilla HTML/CSS/JS, никакой сборки и npm.
- Шрифты: **Syne** (дисплейный, 600/700/800) + **Outfit** (текстовый, 400/500) с Google Fonts.
- Палитра в `:root`: почти чёрный `#070708`, тёплый белый `#f3efe8`, акцент `#e10600`.

## Хронология работ

### 1. Горизонтальный скролл на мобильных

**Симптом:** страница «чуть-чуть листалась» вправо почти на всех телефонах, контент
выглядел смещённым влево, галерея уезжала за край.

**Причина:** два full-bleed хака на `100vw` — у `.floaters` (лента карточек услуг) и
`.film-strip` (галерея):

```css
width: 100vw; left: 50%; margin-left: -50vw;
```

Приём работает, только когда `100vw` точно равен ширине контента документа. Любое
расхождение (скроллбар, зум, различия в трактовке `vw` мобильными браузерами) сдвигает
блок вправо и рождает горизонтальную прокрутку. Плюс `overflow-x: hidden` стоял только
на `body`, без `html` — на iOS Safari этого регулярно не хватает.

**Решение:**
- `.floaters` — full-bleed без единого `vw`: `margin-inline: calc(-1 * var(--space))`
  выводит ленту ровно на горизонтальные паддинги `.hero`. Размер фото при этом переехал
  с обёртки `.hero-photo-wrap` на саму `.hero-photo`, чтобы у ленты была корректная
  опорная ширина.
- `.film-strip` — хак удалён целиком: `.gallery` и так без горизонтальных паддингов,
  полоса была full-bleed и без него.
- `overflow-x: clip` (с фолбэком `hidden`) на `html` и `body`. `clip` не создаёт
  скролл-контейнер, поэтому не ломает фиксированную шапку и smooth-скролл по якорям.
- `overscroll-behavior-x: contain` на обоих горизонтальных скроллерах — свайп по
  галерее больше не «протекает» на страницу.

### 2. Пустота между фото и галереей на планшетах

**Симптом:** на iPad Pro (1024×1366) и Surface Pro 7 (912×1368) перед заголовком
«Кадры из пространства» зияла дыра ~150 px. На больших мониторах — до 300 px.

**Причина:** `.hero { min-height: 100dvh }` и `.hero-stage { min-height: calc(100dvh - …) }`,
а сброс этой растяжки (`min-height: 0`) существовал только в `@media (max-width: 900px)`.
Планшет в портрете широкий, но очень высокий — проваливался мимо сброса. Контента там
примерно на 1215 px, `.hero-stage` — flex-колонка без `justify-content`, остаток уходил
в пустоту снизу.

**Решение:** сброс по высоте вьюпорта, а не по ширине:

```css
@media (min-width: 901px) and (min-height: 1000px) { .hero, .hero-stage { min-height: 0 } }
```

На 1920×1080 и 1440×900 ничего не меняется — там `min-height` и так не срабатывал.

### 3. Оптимизация

| Находка | Было | Стало |
|---|---|---|
| `<link rel="shortcut icon" href="logo.png">` | PNG **2139×2139, 799 KB** в роли фавикона | строка удалена, остались `favicon.png` (1.6 KB) и `logo-64.png` |
| gzip для JS | nginx ≥1.21.4 отдаёт `.js` как `text/javascript`, в `gzip_types` был только `application/javascript` → **JS уезжал несжатым** | тип добавлен, 11.6 KB → 3.5 KB |
| Кэш | `css/js` с `immutable, max-age=604800` при нехэшированных именах — правки не долетали неделю | медиа 30 дней, `css/js` — `no-cache` (ETag/304) |
| Мёртвый CSS | секция `.dj*` (~60 строк, такой секции в разметке нет), `.hero-vignette`, переменные `--glass`, `--radius` | удалено |
| Мёртвый JS | `applySlots` + resize-слушатель дублировали то, что CSS уже делает через `!important` в `@media (max-width: 560px)` | удалено |
| Шрифты | Outfit 300 и 600 не использовало ни одно правило | убраны из запроса |
| Искры на canvas | `ctx.shadowBlur` — программный блюр на CPU, 28 частиц × 60 fps ≈ 1700 блюров/сек | 5 предрендеренных спрайтов + `drawImage` |
| resize для canvas | каждое событие пересоздавало буфер; на мобильных адресная строка шлёт их пачками во время скролла | дебаунс 200 мс + проверка, что размер реально изменился |
| `backdrop-filter: blur(0px)` на шапке | нулевой блюр всё равно держал backdrop-слой | блюр включается только с `.is-scrolled` |
| `COPY logo.png` в Dockerfile | 800 KB в образе | убрано |

Также добавлены `gzip_vary on`, `gzip_proxied any` и `preload` для `hero.jpg`.

### 4. Боковые рейлы Cult / Place

Фоновое слово `CULT` уехало из-под фото на поля экрана:

- **Слева** — `Cult` снизу вверх (`writing-mode: vertical-rl` + `rotate(180deg)`), у нижнего края.
- **Справа** — `Place` сверху вниз, от верхнего края под шапкой.
- Композиция диагональная, не симметричная. У каждого слова хвост-линия, уводящая его
  за край: слева белая, справа неоновая красная — единственное цветное пятно конструкции.
- `position: fixed` — рейлы переживают скролл, как шапка. Живут на уровне `body`, а не
  внутри `.hero`.
- `z-index: 4` — выше секций (`z-index: 3`), ниже шапки (40) и лайтбокса (80).
  `pointer-events: none`.

Первая версия включала их с `min-width: 1200px`, из-за чего на iPad (1024) оставалось
старое центральное слово. Сейчас рейлы работают на всех ширинах, кегль ограничен и
высотой, и шириной экрана: `clamp(1.35rem, min(6.5vh, 7vw), 4.5rem)`. Ниже 700 px они
садятся к самому краю и глушат обводку — там они проходят по краю фотографии.

Центральное `.hero-bg-word` удалено полностью.

### 5. Износ полароидов

Всё на CSS, без единой новой картинки:

- Пятна времени по двум углам поверх бумаги (`radial-gradient` в `background`).
- `::after` — два залома под разными углами плюс потемнение к краям.
- Четыре варианта износа: отражения `::after` по горизонтали, вертикали и обеим осям.
- Два оттенка выцветшей бумаги вперемешку с исходным.
- Снимок: sepia 0.12 → 0.19, темнее и глуше, тонкий тёмный кант по краю фото.
- Подписи повёрнуты на доли градуса, у каждого варианта по-своему.
- Разная посадка по вертикали — лента читается как разложенная стопка, а не ряд.

### 6. Плёночное зерно

`.noise` был сломан: SVG-паттерн 200×200 не имел `background-size` и растягивался на
весь вьюпорт — вместо зерна получались крупные размытые пятна. Добавлен тайл 170 px.

### 7. Анимация лайтбокса услуг

Раньше панель появлялась одним кадром, а закрывалась вообще без анимации.

- Подложка проявляется через `opacity`.
- Панель вырастает **со стороны нажатой карточки**: JS замеряет её `getBoundingClientRect()`
  и отдаёт смещение в `--from-x` / `--from-y`.
- Содержимое въезжает с разбежкой: снимок → название → описание → кнопка.
- У снимка анимируется масштаб, а не сдвиг: панель обрезает по краям, и сдвиг оставил бы
  полосу фона.
- У кнопки анимируется только прозрачность — иначе `transition-delay` достался бы и
  hover-подъёму.
- Закрытие анимировано, `hidden` выставляется после (таймер 320 мс, при
  `prefers-reduced-motion` — сразу).

### 8. Бренд и копирайт

- **Studio → Place** по всем файлам (17 замен): `<title>`, описания, ключевики, og-теги,
  JSON-LD, логотип, заголовок hero, правый рейл, alt-тексты, заголовок карты, подвал.
  Ссылки на соцсети (`cult_minsk`) не трогали — это адреса, а не название.
- **Loft** добавлен в пять мест: эйбрау над заголовком, подпись в подвале, `<title>`,
  og-заголовок, ключевики. В `<h1>` намеренно нет — название бренда должно звучать в одну ноту.
- Подпись галереи: было «Плёнка и полароид — как будто уже был вечер у нас», стало
  **«Кирпич, тёплый свет, глубокие диваны. Приходите — накрыто, прибрано, музыка играет.»**
  Заботу лучше показывать деталями, чем объявлять словом «уютно».

### 9. Ревизия структуры CSS

- Блок полароидов был разрезан пополам: между `.polaroid.is-placeholder` и
  `.polaroid::before` вклинились `.polaroid-lift-*` и `.contacts`. Собран обратно.
- `.nav-toggle` — `place-items: center` рядом с явным `align-items: center` ничего не делал.
- `.glass-card[class*="slot-"]` — второй селектор в правиле с `!important` был лишним.
- `.lightbox-book` — `width: auto; min-width: 0` это значения по умолчанию для inline-flex.
- `-webkit-overflow-scrolling: touch` — iOS 13+ игнорирует.

## Грабли — читать перед правкой

1. **Никаких `100vw` для full-bleed.** Именно это ломало мобильную вёрстку. Выходить на
   края нужно через `margin-inline: calc(-1 * var(--space))` относительно паддингов секции.
2. **`.film-strip` скроллится и по вертикали тоже.** Задан только `overflow-x: auto`,
   значит `overflow-y` вычисляется в `auto`. Отрицательный `margin-top` у полароида
   вытолкнет карточку за падинг и включит вертикальный скролл внутри ленты — только
   положительные отступы.
3. **Варианты полароидов — на классах `polaroid--w2/w3/w4`, не на `:nth-child`.** При
   увеличении карточка клонируется в отдельный слой, где индекс другой: на `:nth-child`
   износ и цвет бумаги менялись бы прямо в момент подъёма.
4. **Отступы разброса заданы через `.film-strip .polaroid--wN`.** Без префикса они
   перебили бы `margin: 0` у поднятого клона — тот позиционируется `fixed` по замеренным
   координатам.
5. **Медиазапросы стоят рядом со своей секцией, а не свалены в конец.** Два блока
   `max-width: 900px` и два `560px` — это не дубли, а разные секции. `max-width: 480px`
   перенести наверх нельзя вообще: `.polaroid { width }` окажется выше базового правила
   и перестанет работать.
6. **Сброс `min-height` у hero — по высоте вьюпорта.** Привязка к ширине уже один раз
   оставила дыру на планшетах.
7. **Слои по z-index:** секции 3 → рейлы 4 → шапка 40 → зерно 50 → лайтбокс 80 →
   слой подъёма полароида 90.

## Беклог

Не сделано, требует решения или внешних инструментов:

- **1.3 MB неиспользуемых картинок** — `gal-04`, `gal-07…10`, `gal-12…14`, `thumb-*.jpg`.
  Похоже на задел для галереи, поэтому не удалялись, но в Docker-образ они едут.
- **`hero.jpg` 454 KB.** Пережатие через `sips` выигрыша не даёт — файл уже плотный.
  Реальная экономия только через WebP/AVIF или `srcset` (мобильному отдавать 720 px
  вместо 1200×1600). Нужен `cwebp`/`sharp`.
- **`assets/images/logo.png`** — 320×320 (45 KB) показывается как 44×44. Замена на
  128-пиксельную версию сэкономит ~40 KB.
- **Ручки для тонкой настройки**, если что-то смотрится слишком сильно или слабо:
  `.noise { opacity }` (сейчас 0.08), `.edge-word { -webkit-text-stroke }` (0.1),
  плотность заломов в `.polaroid::after`.

## Об окружении разработки

В машине, где велась работа, **нет Node и нет Chrome** — прогнать страницу и посмотреть
глазами было нельзя, все правки делались по анализу кода. Стоит проверять результат на
реальных устройствах, особенно мобильную вёрстку и планшеты в портрете.

Полезный сниппет для поиска элемента, вылезающего за экран:

```js
[...document.querySelectorAll('*')].filter(e => e.getBoundingClientRect().right > document.documentElement.clientWidth + 1)
```
